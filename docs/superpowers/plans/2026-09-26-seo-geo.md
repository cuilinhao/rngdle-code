# RNGDLE SEO + GEO 实施计划

> 执行方式：当前任务完成集成，独立的数据与内容工作并行执行，最后统一审查与验收。

**目标：** 按用户提供的 `seo+GEO.md` 完成站内 SEO/GEO、全范围榜单和每日答案归档。

**架构：** 保留 Vite + React 静态预渲染。可见正文和结构化数据使用同一内容模型；数学数据由现有引擎计算；每日快照永久保存，按 UTC 定时构建并部署。

**技术栈：** React 19、TypeScript、Node 22、Vite、Node test、Playwright、GitHub Actions / Vercel。

**规格：** `seo+GEO.md`（作为需求参考，示例中的数字、数学解释、外部产品声明必须核验）。

## 全局约束

- 计数、概率、分数、榜首来自引擎；不更改游戏评分与规则。
- JSON-LD 写入预渲染 HTML head，并与页面可见内容一致。
- 只索引 en / zh；另外四种语言保留访问但 noindex，移出 sitemap 和索引语言互链。
- 不虚构未来答案、上线前历史、发布日期或与其他 RNGDLE 网站的关系。
- 用户原始文档保持原样；提交信息使用中文。

## 审查重点

- UTC 边界、无效日期、未来日期、归档末页和上一日/下一日边界。
- 每日轮换模式与页面展示的确定性候选必须与 makeDaily 一致。
- 全范围榜单必须包括短数字，Top % 包含并列且保留极小非零值。
- 首次 HTML 与客户端导航后的 title / canonical / robots / JSON-LD 一致。
- 英文和中文 FAQ、Schema、静态图片、内链在无 JavaScript 时完整可读。

## 已核实的规格修正

- 文档中的 percentile 示例把上尾占比与传统百分位混淆，正文将使用引擎实际语义。
- 现有 daily 每日轮换一种模式；三组 seed 答案均可生成，但必须标明当天模式及其他模式的性质。
- Google Indexing API 仅适用于 JobPosting / VideoObject 内 BroadcastEvent；本项目通过 sitemap 和 Search Console 请求发现。
- GitHub Actions 使用五字段 `5 0 * * *`，调度时间不等于平台保证精确完成时间。
- 未发布的明日不链接到不存在页面；仅已有日期提供可点击相邻链接。
